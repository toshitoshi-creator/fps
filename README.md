# STEEL PROTOCOL / LAST ISLAND

スマートフォンのブラウザでそのまま遊べる、横画面・タッチ操作の本格FPS。
外部ライブラリ・アセットは一切なし（HTML + CSS + Vanilla JS のみ、描画はレイキャスティング、
効果音とBGMは WebAudio によるプロシージャル生成）。

収録モードは2つ。タイトル画面から相互に行き来できます。

| モード | 入口 | 内容 |
|---|---|---|
| **STEEL PROTOCOL** | `index.html` | 全10ステージのキャンペーン。目標6タイプ・武器6種・敵6種・コイン強化 |
| **LAST ISLAND** | `br/index.html` | バトルロイヤル。1人 + Bot15体、96×96の島、輸送機→降下→漁り→安全地帯→最後の1人 |

## 遊び方

`index.html` をブラウザで開くだけ（ビルド不要）。ローカルサーバで開く場合は:

```bash
node test/serve.js 8080   # → http://localhost:8080
```

スマートフォンは **横画面** にしてください（縦だと回転を促す画面が出ます）。

### 操作

| 操作 | 方法 |
|---|---|
| 移動 | 画面左半分をドラッグ（仮想スティック。触れた場所にスティックが出ます） |
| 視点 / 照準 | 画面右半分をスワイプ |
| 射撃 | FIRE ボタン（フルオート武器は押しっぱなしで連射） |
| リロード | RELOAD ボタン（弾切れ時は自動でも開始） |
| 武器切替 | WEAPON ボタン、または右上の武器スロットをタップ |
| ダッシュ | DASH ボタン（前進中のみ加速） |
| チャージ | TEMPEST RL 装備時は FIRE を押し続けて溜め、離すと発射 |
| しゃがみ / スコープ | CROUCH ボタン（狙撃銃装備時はスコープを覗きます） |
| ポーズ | 右上の ❚❚ |

視点感度の初期値は **200**（ルックゾーンを端から端まで1回スワイプでおよそ115度振り向く）。
SETTINGS のスライダーで 60〜400 の範囲に変更できます。
左利き設定（SETTINGS → 左右反転）で操作系を左右入れ替えられます。
デスクトップでは WASD / マウス / R / Q / 1〜4 / Space でも操作できます（動作確認用）。

## ビジュアルスキン

**POP（既定）** と **MILITARY** を SETTINGS の「ビジュアル」で切り替えられます。
配色・壁テクスチャ・敵とプレイヤー武器の描画・UIのすべてが一括で入れ替わります。

POPを既定にしているのは、将来スキャンした実在の空間で遊ぶことを見据えているためです。
スキャンから起こしたマップは「グリッド状の抽象的な間取り」になるので、リアル志向だと
作りかけの3Dに見えてしまいます。トイ的な表現なら、同じ形状でも意図した世界として成立します。

明るい背景でも敵が沈まないよう、POPでは次の対策を入れています。

- 敵は濃い輪郭の外側にさらに白フチを回した「ステッカー」状にする
  （同系色の床の上でもシルエットが切れない）
- 敵にはフォグをかけず、遠くの背景だけを白側へ寄せる
- HUDは必ず「白地＋濃い輪郭」で抜き、背景の色に影響されないようにする
- 表情（通常／攻撃＝怒り眉／被弾＝×目）で敵の状態が一目で分かる

外部フォントは読み込みません（オフラインでも同じ見た目で動くようにするため）。

## ゲームループ

タイトル → ブリーフィング → 戦闘 → 敵撃破（コイン獲得）→ 目標達成 → クリア画面（評価・報酬）
→ 武器強化 → 次ステージ

進行状況（クリア済みステージ・評価・所持コイン・解放武器・強化レベル・設定）は
`localStorage` に自動保存されます。

### 成長

敵撃破とステージクリアで**経験値**が入り、**レベル**が上がると最大HP・攻撃力・移動速度・
リロード速度が恒常的に伸びます（最大30／到達に約119,000 XP）。
コインによる強化とは別系統なので、遊ぶほど確実に強くなります。

連続撃破で**コンボ**が繋がり、コイン・経験値の倍率が最大 x1.9 まで上がります（被弾で切れる）。

### 敵AI（全6種）

`待機 → 巡回 → 発見 → 追跡 → 攻撃 → 被弾 → 後退/再配置 → 瀕死 → 死亡` の状態遷移を持ち、
視界（距離・画角・遮蔽）に加えて銃声・仲間の死亡・至近距離の気配で警戒します。
経路探索はプレイヤーを起点とした BFS フローフィールドで、袋小路でも止まりません。

| 敵 | 特徴 |
|---|---|
| 一般兵 | バランス型。2点バースト |
| 突撃兵 | 高速で接近して殴る |
| 狙撃兵 | 距離を取る。**レーザー照準で予兆**を出す |
| 重装兵 | 高HP・装甲。3点バースト |
| 精鋭兵 | 高速・高精度。**削られると距離を取って撃ち返す** |
| TITAN-01 | ボス。4フェーズ・4種の攻撃パターン・援軍4波 |

**理不尽さの排除:**

- 攻撃は必ず予兆（windup 0.28〜0.75秒）を挟んでから出る。狙撃兵はレーザーで狙点を可視化
- 同時に攻撃できる敵数に上限があり、全方位から一斉に撃たれない
- 被弾直後の短時間は被ダメージが軽減され、弾が重なっても即死しない
- 拠点確保中は足を止めることを強制されるため、その間だけ被ダメージを軽減

## LAST ISLAND（バトルロイヤル）

`br/index.html`。1試合 = 自分1人 + Bot 15体（設定で 5〜29 体）。

### 流れ

輸送機 → 降下地点をマップでタップ → **DROP** → 自由落下 → 高度26mで自動パラシュート →
着地 → 建物を漁って武装 → Bot と交戦 → 安全地帯が6段階で縮小 → 最後の1人で **VICTORY**。
リザルトで XP とコインが入り、レベル（最大50）とデイリーミッションが進みます。

### 島

96×96 の島に 8つのランドマーク（CENTRAL CITY / MILITARY BASE / INDUSTRIAL / HARBOR /
VILLAGE / FOREST / ROCK RIDGE / LAKE）。建物は必ず入口が開くように生成し、
生成後に到達可能性を検査して、たどり着けない地形と宝箱は取り除きます。
ルートの中身と品質はエリアごとに変わり、MILITARY BASE が最も良い装備が出ます。

### 武器とアイテム

| 種別 | 内容 |
|---|---|
| 武器 | 11種（PISTOL / SMG×2 / AR×3 / SHOTGUN×2 / LMG / DMR / SNIPER）2丁持ち |
| 射撃 | フルオート・セミオート・3点バースト。SNIPER と DMR は弾速のある実弾 |
| 弾薬 | ライト / ミディアム / ヘビー / シェル |
| 防具 | アーマー Lv1〜3（ダメージの55%を肩代わり）、ヘルメット Lv1〜3（頭部被弾を20/35/50%軽減） |
| 消耗品 | 包帯・メドキット・エナジー・フラググレネード |

### 操作（追加ぶん）

| 操作 | 方法 |
|---|---|
| ADS | ADS ボタン（押している間）。スコープ武器は覗き穴表示になります |
| 伏せ | PRONE ボタン（拡散が最小、移動は遅い） |
| 回復 | HEAL ボタン（状況に応じて包帯／メドキットを自動で選択） |
| 投擲 | FRAG ボタン |
| 持ち物 | BAG ボタン（武器の持ち替え・アイテムの使用） |
| 全体マップ | ミニマップ右下の MAP ボタン（タップでマーカー設置） |

ADS感度（ヒップの30〜150%）、エイムアシスト4段階、ジャイロ（OFF / ADS中のみ / 常時）、
ボタンサイズ（80〜130%）と透明度（30〜100%）を SETTINGS で変えられます。

### 3Dキャラクター（PHASE 25.5）

キャラクターは板ポリ（ビルボード）ではなく、**骨格を持つ立体モデル**で描いています。
Unityへの移植はせず、既存のレイキャスティング描画の中に
ソフトウェアラスタライザを足す形で実現しているため、
壁の前後関係・視線判定・当たり判定はこれまでと同じものがそのまま働きます。

| 項目 | 内容 |
|---|---|
| 骨格 | pelvis→spine→chest→neck→head / 肩→上腕→前腕→手 / 腰→腿→脛→足 の19ボーン |
| 体 | N角柱を積んだ23パーツ。頭は顎・頭蓋・頭頂の3段で人の輪郭にしている |
| 装備 | ヘルメット(Lv1〜3)・ベスト・バックパック・手袋・ブーツ・ポーチ・髪型を**独立して着脱** |
| 個体差 | 身長・体格・肌・髪・装備をIDから決定。同じBotは毎回同じ姿になる |
| 武器 | 7クラスすべて3Dモデル（レシーバ・銃身・弾倉・グリップ・ストック・サイト） |
| 保持 | 武器の位置姿勢を先に決め、両手を**2ボーンIK**でグリップと前handguardへ合わせる |
| アニメ | IDLE/WALK/RUN/SPRINT/AIM/FIRE/RELOAD/SWITCH/HIT/CROUCH/PRONE/DEATH/FALL/CHUTE の14種を手続き生成 |
| ライティング | 面法線と平行光源による陰影＋距離フォグ＋足元の接地影 |
| 一人称 | 視点空間に置いた武器＋両手＋袖。三人称と同じ反動・リロード・ADSで動く |
| LOD | 〜9m:フル / 〜19m:簡略 / 〜30m:粗 / それ以遠:従来のビルボード |

プレイヤーとBotは同じ `Character_Base`（同じ骨格・同じアニメーション・同じ装備の仕組み）で、
派生するのは見た目の定義データだけです。

3D描画は `Char3D.enabled` で丸ごと切れます（切っても操作・当たり判定・進行は変わりません）。
自分のモデルを見たいときは、開発用フックの `__br.thirdPerson(true)` で三人称になります。

### Bot

6つの性格（AGGRESSIVE / BALANCED / DEFENSIVE / LOOTER / SNIPER / RUSHER）が
交戦距離・撤退ライン・命中精度・反応速度・漁る時間・詰める確率を変えます。
状態は LANDING / LOOTING / EXPLORING / MOVING_TO_ZONE / SEARCHING / COMBAT /
TAKING_COVER / RETREATING / HEALING / RELOADING / ENDGAME / DEAD の12種類。
遠くのBotほど更新間隔を落とす（0 / 1/20秒 / 1/6秒）ことで、16人でも60fpsを保ちます。

## 実際の場所をマップにする（LiDARスキャン変換）

`tools/scan2map.html` をブラウザで開き、LiDARスキャンのファイルをドロップすると、
実在の建物の間取りがそのまま遊べるマップになります。

対応形式: **OBJ / PLY (ascii・binary) / STL / XYZ**、および間取り図の **PNG / JPG**。
iPhone・iPad Pro の Polycam / Scaniverse / 3d Scanner App から書き出したファイルがそのまま使えます。
「サンプルで試す」でスキャンを模擬した点群を生成できるので、機材が無くても動作を確認できます。

処理の流れ:

1. 点群の広がりから **上方向の軸を自動判定**（Y-up / Z-up どちらでも可）
2. 水平ビンごとの最低点に平面を当てて **床面と傾きを推定**（端末の姿勢誤差 1〜4度を補正）
3. 「床が見えているセル＝歩ける」で **占有グリッド化**
   （腰の高さでスライスすると壁面の点が隣のセルへにじみ、1m幅の通路が塞がるため）
4. ノイズ除去・穴埋め・外周の封鎖・到達できない領域の除去
5. 開始地点と敵を自動配置し、キャンバス上で直接描き足せる
6. **「この端末で遊ぶ」** で同じブラウザのゲームに `CUSTOM` ステージとして登録
   （本編の進行度やステージ解放には影響しません）／
   **「定義をコピー」** で `js/data.js` に貼り付けられるステージ定義を出力

### できること・できないこと

できるのは **「スキャン → 間取り → プレイ可能なマップ」** の変換です。
本作の描画はグリッド式のレイキャスティングなので、床は1面・壁は垂直、段差やスロープ、
天井の高低差、家具の形状は表現されません。スキャンした空間は「実寸の間取り」として反映され、
家具など床を遮る物は障害物セルになります。

点群のメッシュをそのまま3D表示したい場合は WebGL への描画エンジン差し替えが必要で、
モバイルでの処理負荷・当たり判定・視認性の作り直しを伴います（本作では採用していません）。

精度の目安（合成スキャンでの実測・元の間取りとの IoU）:

| スキャン品質 | 点間隔 | 復元精度 |
|---|---|---|
| 通常（LiDAR相当） | 5〜7cm | IoU 0.95 |
| 雑に撮った場合 | 12〜18cm・欠損35%・傾き4度 | IoU 0.94 |
| 極端に疎（LiDARでは通常起きない） | 40cm以上 | 精度は落ちるがセルサイズ自動調整で破綻はしない |

## テスト

実ブラウザ（Chromium）で DOM のボタンとドラッグを実際に操作して検証します。

```bash
node test/playtest.js       # 194項目: STEEL PROTOCOL（起動〜通しプレイ〜セーブ〜スキン切替）
node test/brtest.js         # 254項目: LAST ISLAND（輸送機〜降下〜漁り〜戦闘〜Zone〜勝敗〜報酬＋3Dキャラクター）
node test/tooltest.js       # 40項目: スキャン変換ツール〜ゲームへの登録〜実プレイ
node test/scan2map.test.js  # 35項目: 合成LiDARスキャンからの間取り復元精度（Node単体）
node test/balance.js 5      # 凡庸なボットで全ステージを自動プレイし難易度を計測
node test/shots.js <dir>    # STEEL PROTOCOL の全画面スクリーンショット
node test/brshots.js <dir>  # LAST ISLAND の全画面スクリーンショット
```

Playwright が必要です（`npm i -D playwright`）。`test/scan2map.test.js` だけは Node 単体で動きます。

`playtest.js` は「射撃ボタンが反応しない」「敵に弾が当たらない」「弾数が減らない」
「ゲームオーバーにならない」「セーブできない」といった不具合を個別に検査し、
最後に **タッチ操作だけで STAGE 1 をクリアできること** を通しで確認します。

`brtest.js` はバトルロイヤル側を同じやり方で検査します。DROPボタンで実際に降下し、
パラシュートが開いて着地し、落ちている武器を「拾う」でタップして取得し、
FIREで敵Botを撃ち、安全地帯の外でダメージを受け、最後の1体を倒して VICTORY と
リザルト・XP・コイン・ミッション進行までを通します。あわせて
**操作ボタンが44px以上あること・画面外にはみ出さないこと・HUDの表示と重ならないこと・
押しても何も起きないボタンが無いこと** をレイアウトから機械的に確認します。
さらに3Dキャラクターについて、骨格の整合性・装備の着脱・個体差・14種のポーズが
すべて別の姿勢になること・歩行と死亡が時間で動くこと・武器が手に追従すること・
距離によるLODの切り替わり・一人称の腕と武器が反動とリロードで動くこと・
16人ぶん描いてもフレーム時間が収まることを検査します。

## 設定

BGM / 効果音 / 視点感度（60〜400）/ **エイムアシスト（OFF・LOW・MED・HIGH）**/
描画品質（AUTO・LOW・MID・HIGH）/ 画面揺れ / **振動** / 左右反転 / ビジュアルスキン。
すべて自動保存されます。

エイムアシストは最強設定でも当たり判定の横幅が **1.55倍まで**で、
「狙わなくても当たる」状態にはなりません（テストで担保）。

> **振動について:** iOS Safari は Vibration API を実装していないため、iPhoneのブラウザでは
> 振動しません。Android Chrome とホーム画面に追加した PWA では動作します。
> 未対応環境では設定が「非対応」と表示され、ゲームの動作には影響しません。

## パフォーマンス

内部解像度と1本あたりのレイ幅を実測 FPS に応じて自動調整します（SETTINGS で固定も可能）。
テスト環境（844×390 / 敵9体）でフレーム時間の中央値は約 16.7ms。
